Controlled Text-to-SQL

从一句业务问题，到一条受控查询

模型提出候选 SQL，程序决定它能否执行。点击不同风险场景，逐步查看请求如何穿过前端、Pipeline、安全网关、审批与 MySQL。

项目主原则生成权与执行权分离。即使模型输出错误，AST 校验、表白名单、审批和只读账号仍然独立生效。
请求生命周期 L0 · 安全查询
01

用户提出业务问题

用户在 Vue 工作台输入中文问题；前端只负责收集输入和展示状态，不承担 SQL 安全判断。

当前代码位置frontend/src/App.vue → api.ts

简单查询直达执行

L0

SQL 结构简单且预计扫描量低，自动通过只读网关执行。

复杂查询停在审批

L1 / L2

JOIN、子查询、窗口函数或扫描量过高时，用 SQL 哈希绑定人工审批。

越界能力永久拒绝

L3

写操作、系统库、危险函数、未授权表等没有“管理员强行通过”通道。

Responsibility Layers

四层职责，层层收紧权限

从交互层向数据库靠近，能力越来越少、约束越来越强。模型没有数据库连接；前端也不能决定自己是否是管理员。

01 / EXPERIENCE

交互层

控制层
